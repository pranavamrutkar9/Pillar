## 9. Engineering Process

### 9.1 Repository Structure
```
pillar/
  apps/
    web/             Next.js 14 App Router
      app/           Pages, layouts, loading states
      components/    Reusable UI components
      ui/            shadcn base components
      features/      Feature-specific components (board, issues, adrs)
      lib/           Client utilities, hooks, store (Zustand)
    api/             Express + Node.js
      src/
        routes/      Express route handlers — thin, delegate to services
        services/    Business logic (IssueService, AIService, GithubService)
        workers/     BullMQ job processors — one file per event type
        events/      eventBus.ts + event type definitions
        middleware/  Auth verification, error handling, rate limiting
        db/          Prisma client singleton
        prisma/
          schema.prisma    Single source of truth for all DB tables
          migrations/      Auto-generated by Prisma, never edit manually
  packages/
    types/           Shared TypeScript interfaces — used by both apps
    utils/           Shared utility functions
    config/          Shared ESLint, TypeScript, Prettier configs
  .github/
    workflows/       CI/CD GitHub Actions
  docker-compose.yml Local dev — Postgres + Redis + Qdrant
  pnpm-workspace.yaml
```

### 9.2 Git Workflow
| Branch | Purpose and Rules |
|---|---|
| main | Production only. Never push directly. Merged via PR from develop only. |
| develop | Integration branch. All features merge here first. Deployed to staging. |
| feature/PIL-42-board-view | One branch per issue. Name includes issue ID for traceability. |
| fix/PIL-67-drag-drop-mobile | Bug fixes with issue reference. |
| chore/upgrade-prisma | Non-feature work — deps, config, tooling. |

Rules: feature → develop via PR. develop → main via PR after testing. Squash merge to keep history clean. Never force push. Every PR links to its issue.

### 9.3 Commit Convention
Format: `type(scope): description`
* `feat(issues): add drag-and-drop board view with optimistic updates`
* `fix(auth): resolve GitHub OAuth token refresh on session expiry`
* `chore(deps): upgrade Prisma to 5.10, update generated client`
* `refactor(events): extract eventBus to standalone service module`
* `test(issues): add unit tests for status transition validation`
* `docs(api): document issues endpoint request and response shapes`

Why: automatic changelog generation, readable git history, PR titles that explain what changed at a glance.

### 9.4 CI/CD Pipeline
| Job | Trigger |
|---|---|
| TypeScript type check | Every push to any branch |
| ESLint | Every push to any branch |
| Vitest unit tests | Every push to any branch |
| Build check (Next.js + Express) | Every PR to develop or main |
| Vercel preview deployment | Every PR — automatic preview URL for review |
| Production deploy | Merge to main only — auto via Vercel and Railway |
| Neon branch creation | Every PR — creates isolated DB branch for testing |
| Neon branch deletion | PR closed — cleans up DB branch automatically |

### 9.5 Local Development
Prerequisites: Node 20+, pnpm, Docker Desktop

1. `git clone https://github.com/you/pillar && cd pillar`
2. `pnpm install` — installs all workspace dependencies
3. `docker-compose up -d` — starts Postgres + Redis + Qdrant locally
4. `cp apps/api/.env.example apps/api/.env`
5. `cp apps/web/.env.example apps/web/.env`
6. Fill in: DATABASE_URL (local Postgres), GITHUB_CLIENT_ID, ANTHROPIC_API_KEY
7. `pnpm db:migrate` — runs Prisma migrations
8. `pnpm db:seed` — seeds workspace + test user
9. `pnpm dev` — starts web (3000) and api (4000) concurrently

Total time from clone to running: under 10 minutes. This is also a live demo of your own Onboarding Accelerator philosophy.

### 9.6 Environment Variables
| Variable | Service |
|---|---|
| DATABASE_URL | Prisma — Neon PostgreSQL connection string |
| REDIS_URL | BullMQ — Redis connection (Railway local, Upstash prod) |
| QDRANT_URL + QDRANT_API_KEY | Vector search — Qdrant Cloud |
| NEXTAUTH_SECRET + NEXTAUTH_URL | NextAuth — session signing and redirect URL |
| GITHUB_CLIENT_ID + GITHUB_CLIENT_SECRET | GitHub OAuth for user login |
| GITHUB_APP_ID + GITHUB_PRIVATE_KEY | GitHub App for repo integration and webhooks |
| GITHUB_WEBHOOK_SECRET | Verify authenticity of incoming GitHub webhooks |
| ANTHROPIC_API_KEY | Claude API — all AI features |
| OPENAI_API_KEY | text-embedding-3-small — document and issue embeddings |
| VOYAGE_API_KEY | voyage-code-2 — code file embeddings for Codebase Conscience |
| RESEND_API_KEY | Email notifications |
| CLOUDINARY_URL | File and image storage |
| NEXT_PUBLIC_API_URL | Frontend — points to Express backend URL |
